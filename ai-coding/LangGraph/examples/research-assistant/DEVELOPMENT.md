# Research Assistant 开发文档

## 1. 项目目标

构建一个能够结合本地知识库和 Web 搜索的研究助手 Agent。用户提出问题后，Agent 根据问题类型选择本地检索、Web 搜索或两者，并输出带来源说明的答案。

第一版以教学 Demo 为目标，优先保证流程清晰、代码可运行，不提前引入复杂的生产基础设施。

## 2. 技术分工

| 模块 | 技术职责 |
| --- | --- |
| LangChain | 文档加载、文本切分、向量检索、模型调用、工具定义 |
| LangGraph | Agent 状态、节点、条件路由、工具执行和结果汇总 |
| 本地知识库 | 提供稳定、可复现的 RAG 数据 |
| Web 搜索 | 获取实时信息和本地知识库之外的内容 |

## 3. 目录结构

```text
research-assistant/
├── README.md
├── DEVELOPMENT.md
├── agent.py          # LangGraph 工作流入口
├── rag.py            # 本地文档加载与检索
├── web_search.py     # Web 搜索工具
├── prompts.py        # Agent 提示词
├── requirements.txt  # Demo 依赖
└── .env.example      # 环境变量模板
```

## 4. 初步工作流

```text
用户问题
   ↓
问题分析与路由
   ├── 仅需本地知识 → RAG 检索
   ├── 需要实时信息 → Web 搜索
   └── 两者都需要   → 并行或依次检索
                         ↓
                    结果汇总
                         ↓
                  生成带来源的答案
```

## 5. 状态设计

第一版预计使用以下状态字段：

```python
class ResearchState(TypedDict):
    question: str
    route: str
    retrieved_documents: list
    web_results: list
    answer: str
    sources: list
    error: str | None
```

字段保持最小化。只有在实际流程需要持久化、人工审批或多轮研究时再增加字段。

## 6. 开发阶段

### 阶段一：目录与接口

- 创建模块文件和环境变量模板；
- 确定 `ResearchState`；
- 明确 RAG 和 Web 搜索的输入输出格式。

验收标准：目录结构清晰，开发者能够根据文档继续实现。

### 阶段二：最小 RAG

- 准备少量本地 Markdown 文档；
- 实现文档加载、切分和检索；
- 输出文档内容及来源。

验收标准：给定问题能够返回相关文档片段和文件名。

### 阶段三：Web 搜索工具

- 定义统一的搜索工具接口；
- 接入一个具体搜索服务；
- 统一搜索结果的标题、摘要、链接和时间字段。

验收标准：工具失败或超时时能返回可识别的错误。

### 阶段四：LangGraph 编排

- 添加问题分析节点；
- 添加 RAG 和 Web 搜索节点；
- 添加条件路由和结果汇总节点；
- 生成带来源的最终回答。

验收标准：本地问题、实时问题和混合问题都能走正确路径。

### 阶段五：可靠性与安全

- 为网络错误设置有限重试；
- 为模型和搜索工具设置超时；
- 对搜索失败提供降级结果；
- 不在日志中输出 API Key；
- 如增加有副作用的工具，再接入人工审批。

验收标准：失败不会导致 Agent 无限重试，也不会绕过权限控制。

## 7. 路由原则

- 涉及本地资料、项目文档或内部知识：优先使用 RAG；
- 涉及新闻、价格、天气、最新版本等时效性内容：使用 Web 搜索；
- 需要结合内部资料和外部事实：同时使用 RAG 与 Web 搜索；
- 无法判断时，优先询问用户或使用成本较低的检索方式；
- 最终答案区分“本地资料结论”和“Web 搜索结论”。

## 8. 错误处理

| 场景 | 处理 |
| --- | --- |
| 临时网络错误 | 有限重试，指数退避 |
| 搜索超时 | 使用已有结果或明确告知未完成实时查询 |
| RAG 没有相关内容 | 不编造内部资料，必要时转 Web 搜索 |
| Web 搜索没有结果 | 返回无法确认，并建议缩小问题范围 |
| 模型无法汇总 | 返回检索结果和来源，保留原始信息 |
| 权限或认证失败 | 停止调用，不重复重试 |

## 9. 环境变量

具体供应商确定后，再将真实变量补充到 `.env.example`。API Key 只保存在本地 `.env` 或部署平台的密钥管理中，不提交到 Git。

## 10. 暂不实现的内容

- 多 Agent 协作；
- 长期记忆；
- 复杂向量数据库部署；
- 自动引用质量评分；
- 多供应商自动切换；
- Web UI 和独立服务部署。

这些内容等最小流程跑通后，再根据实际需要增加。
