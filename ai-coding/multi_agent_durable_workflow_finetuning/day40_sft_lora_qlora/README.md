# Day 40：SFT 与 LoRA/QLoRA（衔接 Day 41）

本目录是 Day 40–41 训练阶段的**学习大纲与知识总结**，尚未实现训练 Demo。目标是在 Day 39 已确认“值得微调”且训练/验证/测试集已冻结的前提下，微调一个小模型的**结构化退款结论或只读工具调用能力**，监控过拟合，并在封存测试集上与未微调基线对比。若 Day 39 的结论是 No-Go，应记录理由并停止，不为了完成训练步骤而训练。

## 一、阅读资料与工具选择

- [LLaMA-Factory](https://github.com/hiyouga/LlamaFactory)：面向多模型、多训练方法的 CLI/Web UI。适合先用配置文件跑通一个可重复的 SFT/LoRA 实验；数据格式以所选版本的官方说明为准。
- [Unsloth](https://github.com/unslothai/unsloth)：另一条小模型训练实现路径。与 LLaMA-Factory **二选一作为实验入口**，避免一次实验同时更换模型、训练框架和数据格式。
- [Hugging Face PEFT](https://huggingface.co/docs/peft/index)：理解 Adapter/LoRA 的原理与保存方式；[量化与 QLoRA 指南](https://huggingface.co/docs/peft/developer_guides/quantization)解释在量化基础模型上训练 LoRA Adapter 的做法。

开始前检查所选模型的许可证、可用训练格式、Tokenizer/Chat Template、硬件与显存、工具链版本。QLoRA 依赖具体量化后端和硬件支持；**不要假定任意 CPU/Mac/显卡都能运行同一份 4-bit 配置**。资源不足时缩小模型、样本或序列长度，或只完成数据转换与基线复评，不伪称完成 QLoRA。

## 二、学习内容总结

| 概念 | 要点 | 本次实验中的作用 |
| --- | --- | --- |
| SFT（监督微调） | 用输入与期望输出示例训练模型，优化模仿目标行为 | 学习稳定输出 JSON/工具调用格式与窄任务判断 |
| 全参数微调 | 更新大部分或全部基础模型权重，资源开销较高 | 只作对照概念，不作为本次最小实验默认方案 |
| LoRA | 冻结基础模型权重，训练少量低秩 Adapter 参数 | 优先尝试的参数高效 SFT 方法 |
| QLoRA | 在量化基础模型上训练 LoRA Adapter，主要降低模型权重占用 | 仅在硬件/后端支持且 LoRA 显存不足时尝试；量化也可能影响质量/速度 |

LoRA/QLoRA 是**怎样更新参数**，SFT 是**用什么训练目标**；所以“SFT + LoRA”并不矛盾。Adapter 不是完整基础模型：复现推理结果还要记录基础模型精确版本、Tokenizer、Chat Template、Adapter 版本和推理参数。训练成功不等于业务成功，最终仍以独立保留集为准。

### 任务与数据边界

沿用 Day 39 的假订单任务，先只选一个目标：① 结构化退款结论；或 ② 从 `mock_order`、`mock_refund_rules` 中选择合适的**只读**工具及参数。不要在最小实验同时训练两个目标、混入真实支付写工具或把工具输出中的任意指令当系统指令。训练样本必须是审核过的正确示范；错误工具轨迹只用于评估或显式构造的拒绝示例，不能不加处理地作为正向标签。

训练集用于拟合，验证集用于选轮次/检查过拟合，封存测试集只在最终候选确定后使用。对比时固定模型任务、Prompt、工具 Schema、解码设置、评分器和测试集；记录训练前后逐样本结果，不能仅比较训练 loss。

### 如何识别过拟合

- 训练 loss 持续下降，验证 loss 停滞或上升，是一个预警；更关键的是验证集的 JSON/Schema 合法率、工具选择与参数准确率是否开始变差。
- 检查按任务类别和边界样本分组的表现。平均分上升但危险工具误调用率上升，仍应判为不合格。
- 优先保留验证集表现最好的 Checkpoint/Adapter；如果训练集显著提升但验证集没有收益，停止增加轮次并复查数据泄漏、标签质量和任务定义。

## 三、Task / Project 学习路线

### Task 1：确认训练前提与实验契约

- 读取 Day 39 的 Go/No-Go 决策、去重报告、数据版本和未微调基线；明确只优化一个窄目标。
- 固定基础模型版本、任务输入/输出 Schema、Prompt/Chat Template、工具权限、评分器和硬件预算。
- **产出/验收**：一页实验卡；缺少独立测试集或能力缺口证据时不启动训练。

### Task 2：将规范样本转换为训练格式

- 将 Day 39 的规范样本转换成所选工具链要求的对话格式；对工具任务保留工具名、参数、工具结果与最终答案的角色/顺序。
- 检查目标输出可解析、标签与工具 Schema 一致、样本未跨集泄漏；仅对训练集执行可能影响学习分布的数据增强。
- **产出/验收**：转换规则、少量可人工阅读的样例、自动校验报告和 train/validation/test 哈希。

### Task 3：跑通最小 SFT + LoRA

- 选 LLaMA-Factory **或** Unsloth；先用少量训练样本做短跑，确认加载、Tokenizer、loss mask、保存 Adapter 和重新加载推理都正常。
- 正式实验固定随机种子，记录学习率、LoRA rank/alpha、目标层、batch、梯度累积、序列长度、训练轮数和依赖版本。
- **产出/验收**：配置、训练日志、可加载的 Adapter，以及在少量不参与训练的验证样本上的推理结果。短跑成功不等于模型质量达标。

### Task 4：有条件地尝试 QLoRA

- 只有在所选设备/量化后端支持且确有显存约束时，保持模型、数据和评分器不变，改用量化基础模型 + LoRA Adapter。
- 比较显存峰值、耗时、训练稳定性与验证质量；若后端不支持，记录未运行原因，不用 CPU 模拟结果冒充 QLoRA。
- **产出/验收**：可复现的配置或明确的“不适用”结论；不能把更省显存直接等同于更高质量。

### Task 5：监控验证集并选择候选版本

- 记录每次评估的训练/验证 loss、格式合法率、正确率、工具选择/参数准确率、危险写工具误调用率。
- 根据预先设定的选择规则选 Adapter；对失败案例做归因，不根据测试集调整训练轮次。
- **产出/验收**：训练曲线或逐轮表格、选定版本及理由、过拟合/退化检查。

### Task 6：封存测试集上的同题对照

- 在同一测试集上运行未微调基线与最终候选，逐样本比较质量，并记录推理延迟、Token、显存/部署成本及安全回归。
- 若提升不明显、成本不划算或安全指标退化，保留基线；明确 Adapter 回滚方式。
- **产出/验收**：含总体和分组指标的对照报告、失败案例、模型/数据/Adapter 版本与 Go/No-Go 上线结论。

## 四、完成标准

- 训练数据和验证/测试集的隔离可审计，测试集没有用于调参。
- 有未微调基线、训练配置、Adapter、验证曲线和封存测试集的逐样本对照；如硬件不具备训练条件，明确记录未完成项。
- 结构化输出或工具调用能力至少有一个指标可量化地改善，且危险写工具误调用不增加；否则结论是“不采用微调版”。
- 能解释 SFT、LoRA、QLoRA 的不同维度，以及为何本次选择或放弃 QLoRA。
