# 互斥锁

`Mutex` 是 **Mutual Exclusion** 的缩写，中文叫：

> **互斥锁**

拆开：

- **Mutual** = 相互的
- **Exclusion** = 排除
- **Mutex** = 相互排斥的锁

简单理解：

> **同一时间，只允许一个线程（goroutine）访问某个共享资源。**

------

## 为什么需要 Mutex？

Go 里面有一个特点：

> goroutine 很轻量，可以同时运行很多个。

例如：

```go
package main

import (
	"fmt"
	"sync"
)

var count int

func add() {
	for i := 0; i < 1000; i++ {
		count++
	}
}

func main() {
	go add()
	go add()

	// 等待结束（这里省略）
	fmt.Println(count)
}
```

你以为结果：

```
2000
```

但是可能得到：

```
1873
```

为什么？

因为：

```go
count++
```

不是一个原子操作。

它实际上分三步：

```
1. 读取 count
2. 加 1
3. 写回 count
```

两个 goroutine 可能同时：

```
goroutine A        goroutine B

读取 count=10      读取 count=10

+1                 +1

写入11             写入11
```

结果：

```
11
```

而不是：

```
12
```

这叫：

> 数据竞争（Race Condition）

------

# Mutex 怎么解决？

加锁：

```go
package main

import "sync"

var (
	count int
	mutex sync.Mutex
)

func add() {
	for i := 0; i < 1000; i++ {
		mutex.Lock()

		count++

		mutex.Unlock()
	}
}
```

现在流程：

```
goroutine A:

Lock()
  修改 count
Unlock()


goroutine B:

等待...

Lock()
  修改 count
Unlock()
```

同一时间只有一个 goroutine 能修改 `count`。

------

# Mutex 的两个核心方法

## 1. Lock()

加锁：

```go
mutex.Lock()
```

意思：

> 我要进入临界区，其他人不能进。

------

## 2. Unlock()

解锁：

```go
mutex.Unlock()
```

意思：

> 我操作完成了，别人可以进来了。

------

通常写：

```go
mutex.Lock()
defer mutex.Unlock()

// 修改共享数据
```

例如：

```go
func add() {
	mutex.Lock()
	defer mutex.Unlock()

	count++
}
```

为什么用 defer？

因为如果中间报错：

```go
mutex.Lock()

doSomething()

// 忘记 Unlock()
```

可能导致：

> 永久死锁（deadlock）

------

# Mutex 在实际项目中的场景

## 1. 保护共享变量

例如：

```go
type Counter struct {
	value int
	mutex sync.Mutex
}

func (c *Counter) Add() {
	c.mutex.Lock()
	defer c.mutex.Unlock()

	c.value++
}
```

------

## 2. 保护 map

Go 的 map 不是线程安全的。

错误：

```go
data := map[string]int{}

go func(){
	data["a"] = 1
}()

go func(){
	data["b"] = 2
}()
```

可能：

```
fatal error: concurrent map writes
```

解决：

```go
var mu sync.Mutex

mu.Lock()
data["a"] = 1
mu.Unlock()
```

------

## 3. 文件写入

例如多个 goroutine 写日志：

```
goroutine 1
      \
       \
        ---> log.txt
       /
goroutine 2
```

可能互相覆盖。

使用 Mutex：

```go
mutex.Lock()

file.Write(data)

mutex.Unlock()
```

# Go 里面还有一种：RWMutex

除了：

```go
sync.Mutex
```

还有：

```go
sync.RWMutex
```

意思：

> Read Write Mutex（读写锁）

区别：

## Mutex

只有一种锁：

```
读   等待
写   等待
```

一次只能一个。

------

## RWMutex

允许：

```
多个读
一个写
```

例如：

数据库缓存：

```
100个请求读取配置

1个请求更新配置
```

读可以并发：

```
Reader
Reader
Reader
      \
       Cache
      /
Reader
```

写的时候：

```
Writer

其他全部等待
```

代码：

```go
var mu sync.RWMutex

// 读
mu.RLock()
value := data
mu.RUnlock()

// 写
mu.Lock()
data = newData
mu.Unlock()
```

------

# Mutex 和 Java 的 synchronized 类似

如果你之前接触过 Java：

Java：

```java
synchronized(lock) {
    count++;
}
```

Go：

```go
mutex.Lock()
count++
mutex.Unlock()
```

作用类似。

------

# 一句话总结

`Mutex`：

> **一种保证并发安全的锁，让多个 goroutine 访问共享数据时，按照顺序一个一个执行，避免数据被同时修改导致错误。**

在 Go 后端开发中，常见用途：

- 保护共享变量
- 保护 map
- 控制资源访问
- 实现线程安全的数据结构

你后面学习 Go Web 服务、Redis 缓存、任务队列时，会经常看到 `sync.Mutex`。
